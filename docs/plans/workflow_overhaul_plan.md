## 3. User's Questions — Answered

### "Dedup uses queryHash — is that independent for each run?"
**Answer:** Global dedup. The `queryHash` prevents the same search from executing twice across ALL runs. A time bucket component ensures queries eventually re-execute for freshness. This is correct behavior — saves API credits.

### "Country code should be country"
**Answer:** Confirmed. `countryCode` stores "AE", "SA". Will add a `country` display name field and a code-to-name mapping in the UI.

### "Shouldn't scraping come BEFORE Hunter/Apollo?"
**Answer:** Yes, this is the single highest-ROI change. Current order: Hunter → Apollo → scrape. New order: scrape → SMTP verify → use scraped contact (skip Hunter) OR fall back to Hunter if no valid email found.

### "Why Business Records if we have Lead Records?"
**Answer:** Business records serve real purposes: dedup across searches, pre-qualification gate, one-to-many (multiple contacts at one company), company-level metadata. The fix is surfacing them in the UI (Business Intelligence view), not removing them.

### "Is People Data Labs free?"
**Answer:** No. PDL charges per API call. The enrichment provider order should be reversed to cheapest-first: OTHER_FREE → HUNTER → PDL.

### "How do we ensure cross-source data alignment?"
**Answer:** Build a Data Alignment Score with tiered response:
- < 0.3: Hard filter (don't message — data sources are for different entities)
- 0.3-0.5: Weighted feature in scoring (model learns to downweight)
- > 0.5: Proceed normally

### "Feature values should be displayed in lead detail pages"
**Answer:** Will be addressed by the Business Intelligence view + enriched lead detail page.

### "For message generation, use website and Instagram data"
**Answer:** Session C will build a `buildMessageContext()` function converting raw scrape JSON into structured intelligence. Research-backed template structure: 40-80 words, timeline hook opener, specific observation from their business, social proof with number, single interest-gate CTA.

### "Ensure replies shown in Inbox page"
**Answer:** Session A will verify inbox entries correlate to real FeedbackEvents. Session D will ensure webhook handlers correctly create displayable entries.

### "For sales notification, send email to peem.pibuldham@axiom-8.com"
**Answer:** Session C will add Resend email channel to `notify.sales.job.ts`. Will notify on ALL reply types (interested, not interested, OOO, unsubscribe).
